# DSI Redline v1.1.0 — New Features & How They Work

This release came from a user-group feedback sprint. Below is each new feature:
**what it does**, **how to use it**, and a short **how it works** for the
technically curious. It closes with the design principles that keep every mark
portable, editable and lossless.

---

## The foundation (how markup is stored)

Everything below builds on DSI Redline's **hybrid storage** model, so it's worth
knowing up front:

- Your **original PDF is never modified.**
- Marks are written into a **`<name>.marked.pdf`** copy as *standard PDF
  annotations*, so they open in Adobe, Chrome, Edge, etc.
- App-only state (TODO status, tags, styling, geometry) lives in a
  **`<name>.markup.db`** SQLite **sidecar**, which is the **source of truth** for
  marks this app created.

Internally, every mark — highlight, pen, rectangle, arrow, comment, text box,
callout, cloud — is a single `Annotation` record. The on-screen canvas draws each
one as its own overlay item; the model layer stays free of any UI code and simply
notifies the canvas, the Comments sidebar and the TODO tab when something
changes. Every edit is a command on the undo stack, so **everything is undoable.**

## 1. Notes on any mark

**What:** Any mark — not just comments and text boxes — can carry a written
**note**. Previously only sticky-note comments and text boxes held text.

**How to use:** Right-click a highlight, pen stroke, rectangle, arrow or cloud →
**Add note… / Edit note…**. A noted mark shows a small **orange badge**, appears
in the **Comments** sidebar, and (on export) becomes a real comment (see #8).

**How it works:** The mark's existing `text` field doubles as the note. Two
derived flags — "has a note" and "belongs in the Comments list" — drive the
sidebar, which now also offers **Rectangle / Arrow / Callout / Cloud** type
filters. The badge is a tiny child graphics item pinned to the mark's corner. The
note editor is the same dialog used for comments, and the change is pushed to the
undo stack, so adding or clearing a note undoes/redoes cleanly.

---

## 2. Opaque text boxes & rectangles (fill + opacity)

**What:** Rectangles and text boxes can carry an **interior fill** with an
adjustable **opacity** — from 0 (no fill) through translucent shading to a fully
opaque **cover** (e.g. white) that hides what's beneath, useful for redlining out
an area.

**How to use:** Pick the **Rectangle** or **Text box** tool, click the toolbar
**Fill** button, choose a colour and drag the **opacity slider** (0% = none,
100% = opaque cover), then draw. Text boxes also expose a Fill control in their
editor; rectangles expose **Fill…** on right-click to change it later.

**How it works:** Each mark gained a fill colour + fill opacity. On the canvas the
shape paints its fill beneath its border/text. On export a rectangle's fill is
written as the annotation's interior colour and a text box's as its background,
with the opacity applied — so the fill renders in any PDF reader and round-trips
back when reopened.

> **A note on the opacity control:** the first build used a raw "alpha channel"
> inside the colour picker, which wasn't obvious. It's now a plain, labeled
> **opacity slider** with an explicit "No fill" option.

## 3. Callout tool

**What:** A text box with a built-in **leader arrow** that points at whatever
you're calling out.

**How to use:** Pick **Callout**, drag out the text box, type the note, then drag
the **orange tip** so the arrow points at the target. The box still moves,
resizes and edits like a normal text box (it doesn't rotate).

**How it works:** A callout is exported as a genuine PDF *FreeText callout* — a
text box plus a leader line ending in an arrowhead. The app stores the arrow-tip
target as its own point; the leader automatically attaches to the nearest edge of
the box, so it stays connected as you move or resize the box. (The leader export
requires a modern PDF engine; on older ones it degrades gracefully to a plain
text box.)

---

## 4. Revision-cloud tool

**What:** A scalloped **revision cloud** for marking areas — outline only, the way
reviewers circle a change on a drawing.

**How to use:** Pick **Cloud**, then choose whichever fits:
- **Drag** — freehand lasso.
- **Shift + drag** — a rectangular cloud.
- **Click** each corner, then **double-click** (or press **Enter**) — a polygon.
  **Esc** cancels an in-progress polygon.

**How it works:** The cloud's outline is generated by walking the path and drawing
a series of outward semicircular "bumps," so any shape — freehand, rectangle or
polygon — becomes a proper scalloped cloud. On export it's written as a PDF
polygon carrying the standard *cloudy border effect*, so other viewers draw the
scallops too.

## 5. TODO audit strikethrough

**What:** Completing a TODO now **strikes it through** so an audit reads at a
glance — both on the drawing and in the list.

**How to use:** Flag a mark as a TODO (in its editor or the TODO tab), then tick
its **Done** box. A **line is drawn across the mark on the sheet**, and its **row
in the TODO list is struck out and dimmed.** Unchecking clears both.

**How it works:** Checking "done" adds a strikethrough overlay across the mark and
restyles the list row. Because the whole app listens to the same model, ticking
the box in the list updates the mark on the canvas instantly, and vice-versa.

---

## 6. Save As — fork to a new working file

**What:** Make a **copy** of your current markup as a brand-new working file and
switch to editing the copy, leaving the original untouched — handy for a
"what-if" revision or a per-reviewer branch.

**How to use:** **File ▸ Save As…** (`Ctrl+Shift+S`), pick a new name. The title
bar switches to the copy; the original is unchanged.

**How it works:** Save As writes a pristine copy of the source PDF under the new
name, starts a **fresh sidecar** there carrying every current mark, wire number,
component label and sheet number, writes the new file's `.marked.pdf`, and points
the app at the copy. From then on your edits land on the fork; the file you forked
*from* keeps its own separate history.

---

## 7. Toolbar reorganisation & tool hotkeys

**What:** The toolbar is grouped by purpose, and every tool has a keyboard
shortcut.

**How to use:** Tools now read in logical groups — **Select** · Highlight / Pen /
Eraser · Comment / Text box / Callout · Rectangle / Arrow / Cloud. Press
**`Ctrl` + a number** to pick a tool in that order: **Ctrl+1** Select … **Ctrl+9**
Arrow, **Ctrl+0** Cloud. Each tool's tooltip shows its shortcut.

---

## 8. Notes exported as visible comments

**What:** A note on any mark now also shows up as a **clickable comment** in every
PDF viewer, not just inside this app.

**How to use:** Nothing extra — add a note (see #1) and save. Open the
`.marked.pdf` in Adobe/Chrome and you'll see a comment icon you can click.

**How it works:** When exporting, a noted mark also emits a standalone
**sticky-note comment** carrying the note text, positioned at the mark's corner.
It's tagged internally so that reopening the file **here** doesn't create a
duplicate — the note is recognised as already belonging to its parent mark.

---

## 9. "It renders in Adobe/Chrome but not in my quick-preview" — the flattened export

Standard PDF markup (fills, clouds, callouts, comments) renders correctly in
proper PDF viewers (Adobe Acrobat, Chrome, Edge) because those honour each
annotation's baked-in **appearance stream**. Some lightweight viewers and file
**thumbnail** previewers ignore annotations entirely and show a blank drawing.

**What:** A one-click **flattened** export for maximum compatibility.

**How to use:** **File ▸ Export flattened PDF (for sharing)…**. The result renders
your marks in **every** viewer, including thumbnails.

**How it works:** The flattened copy **bakes** the marks directly into the page
content (rather than leaving them as separate annotations), while keeping the page
vectors intact. It isn't re-editable — that's the trade-off — but your normal
working file stays fully editable, so you lose nothing.

## Design principles carried throughout

- **The original is sacrosanct** — it is never written to.
- **The sidecar is the source of truth** — marks, TODO state, tags, geometry and
  cached extractions all persist there and round-trip exactly.
- **Everything is a standard PDF annotation on export**, so colleagues can view
  (and comment on) your redlines in their own tools.
- **Everything is undoable** — create, move, resize, rotate, fill, note, delete.
- **The model has no UI knowledge** — the canvas, Comments sidebar and TODO tab
  all react to the same change events, which is why edits stay in sync across the
  whole app.
