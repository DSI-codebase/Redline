# DSI Redline — What's New since v1.1.0

Everything added in **v1.2.0** and **v1.3.0**, in one place. If you skipped the
v1.2.0 update, all of this is new to you.

Each entry says **what** it does, **how to use it**, and — for the curious — a
short **how it works**. Version tags (`1.2` / `1.3`) mark which release each
landed in.

Throughout, the ground rules haven't changed: your **original PDF is never
modified**, marks are written into a `<name>.marked.pdf` copy as standard PDF
annotations, app-only state lives in a `<name>.markup.db` **sidecar**, and
**everything is undoable**.

---

## 1. Marking up faster

### Copy & paste marks `1.2`

**What:** Copy and paste text boxes, callouts, rectangles, circles, arrows, lines
and clouds — within a page or across pages.

**How to use:** Select one or more marks, **`Ctrl+C`** (or right-click ▸
**Copy**), then **`Ctrl+V`** (or right-click empty canvas ▸ **Paste … here**).
Repeated pastes **cascade** so they don't stack; pasted marks land **selected**
and undo as **one step**. With no mark selected, `Ctrl+C` still copies selected
*text*.

**How it works:** Copying snapshots each mark; pasting clones them with fresh
identities, offsets them, and drops them on top of the stack.

### Format painter `1.2`

**What:** Copy one mark's **look** — color, opacity, fill, border width, font —
onto another, without touching its text or position.

**How to use:** Right-click a mark ▸ **Copy formatting**, then right-click
another mark **of the same type** ▸ **Paste formatting**.

**How it works:** Only styling fields transfer, never geometry or words, and only
between marks of the same kind — so a rectangle's fill can't land on an arrow
that has none.

### Sticky styles `1.2`

**What:** New marks **remember your last look**, so you stop re-picking color,
font and fill for every one.

**How to use:** Style a new text box or callout; the **next** one starts with
those settings. The **text is never carried over** — only the styling.

### Stacking order `1.2`

**What:** Control which overlapping mark sits on top.

**How to use:** Right-click a mark ▸ **Order ▸** Bring to Front / Bring Forward /
Send Backward / Send to Back.

**How it works:** Every mark carries a stacking value. It's undoable, **persists**
in the sidecar, and is **honored in the exported PDF** — the layering you see is
the layering colleagues see.

### Smoother "Draw new" `1.2`

**What:** Drawing a new mark on top of an existing one no longer interrupts your
stroke.

**How to use:** Start a mark over another → you're asked once (**Edit / Draw new /
Cancel**). Choose **Draw new** and finish placing it with **no second pop-up**.

### Rename a commenter `1.2`

**What:** Fix **who a mark is by** — handy for a batch imported under a name like
`AutoCAD`.

**How to use:** **Double-click a name** in the Comments **By** column or the TODO
**Commenter** column. Confirm, type the new name — and rename **everyone** by
that name at once if you like. Undoable.

## 2. New and changed drawing tools

### Circle and Line tools `1.3`

**What:** Two new shapes. **Circle** behaves exactly like the rectangle; **Line**
behaves exactly like the arrow, without the arrowhead.

**How to use:** Pick **Circle** or **Line** from the shapes group on the toolbar
and drag. Circle takes a **Fill** (and right-click ▸ *Fill…* to change it later),
resizes, rotates, stacks and copy/pastes just like the rectangle.

**How it works:** Each is the existing shape with a different painter, so every
behavior comes along for free. They export as genuine PDF **Circle** and **Line**
annotations and reload correctly — arrows and lines are both PDF "Line" annots, so
they're told apart on reload by whether the annotation carries an arrowhead.

> **Shortcuts:** the tool shortcuts are now pinned per tool, so adding these
> didn't shuffle the ones you know — **Ctrl+1** Select … **Ctrl+9** Arrow,
> **Ctrl+0** Cloud are unchanged. Circle and Line are a click away on the toolbar.

### Callouts are drawn arrow-first `1.3`

**What:** A callout is now placed **arrow first**, so you aim it at the target
before you decide where the note sits.

**How to use:** Three clicks:

1. **Click what the arrow should point at.**
2. **Click again where the arrow ends** — that's also where the box starts.
3. **Drag out the box** from there and **click to finish**, then type the note.

**`Esc`** cancels at any stage. Afterwards the box moves, resizes and edits exactly
as before, and the orange **tip** grip re-aims the arrow.

**How it works:** The first click sets the target and previews a live arrow; the
second fixes the arrow's end and switches the preview to the box with its leader
attached; the third commits and asks for the text.

### A callout's arrow travels with its box `1.3`

**What:** Moving a callout now takes its arrow along, keeping the same offset —
instead of leaving the tip pinned to the page point it was drawn at.

**How to use:** Just drag the box. To re-aim the arrow, drag the orange tip as
before. **Resizing** the box leaves the arrow pointing where you put it.

**How it works:** A move shifts the arrow's target by the same amount. Resizing
and undo also move the box internally, so the "follow" is deliberately suppressed
for those — otherwise the arrow would creep every time you resized or undid.

## 3. Your workspace

### Movable, floatable tabs `1.2`

**What:** The five main panes — **Viewer, TODO, Wire Numbers, Component Labels,
PDF Tools** — are no longer fixed tabs. Pull one into its **own window** (the TODO
list on a second monitor) or dock it to another edge.

**How to use:** **Drag a tab's title bar** out to float it, or onto an edge to
dock it. Reopen a closed pane from **View ▸ Panes**; **View ▸ Reset panel layout**
restores the default. Your arrangement is **remembered between sessions**.

### Second viewer — the reference pane `1.3`

**What:** A second, **read-only** view of the same PDF, for keeping a **legend,
TOC or cover sheet** on screen while you work on another page.

**How to use:** **View ▸ Reference viewer** (**`F8`**). It **scrolls
independently** (and `Ctrl`+scroll zooms it on its own), and marks you make in the
main viewer **appear in it live**. Dock or float it like any other pane; it stays
hidden until you ask for it.

**How it works:** Both views share one document and one set of marks, which is why
they stay in sync. The pane is deliberately read-only so there's never any doubt
about which view the toolbar or `Ctrl+Z` acts on — drawing and undo always belong
to the main viewer. (The toolbar's zoom, rotate, page and **Find** controls also
drive the main viewer.)

### Recent files `1.3`

**What:** The last **10** drawings you opened, ready to reopen.

**How to use:** **File ▸ Open Recent**, newest first. **Clear list** empties it.

**How it works:** The list is remembered between sessions. Reopening a file moves
it back to the top rather than adding a second entry, and a file that's since
moved or been deleted stays listed but grayed out as *(not found)* — it may just
be on a disconnected drive — rather than silently disappearing.

## 4. Printing, reading and getting it out

### Print — with preview and "Include markups" `1.2`

**What:** Print the drawing, with or without your marks, to any installed printer.

**How to use:** **File ▸ Print…** (**`Ctrl+P`**) opens the **standard system print
dialog** — printer, copies, orientation, page range. **File ▸ Print preview…**
shows the pages first and adds an **Include markups** toggle (**on by default**)
so you can print either the marked-up drawing or a **clean** copy.

**How it works:** Each page is rasterized — marks baked in, or clean if the toggle
is off — then fitted and centered on the sheet.

### Sharper prints `1.3.1`

**What:** Printed pages come out **crisp** — fine line work, thin wires and small
title-block text hold up instead of looking soft.

**How to use:** Nothing to change — print as usual.

**How it works:** Each page used to be rasterized at a fixed 200 dpi relative to
the drawing and then **stretched** to fill the sheet, so what reached the paper
was a magnified low-resolution image. Pages are now rasterized at a **600 dpi**
working resolution and drawn **1:1** into the printer's own page geometry, with
no enlargement — about three times the detail that used to reach the paper.

> The 600 dpi is the app's own working resolution, not the driver's. The quality
> setting in your printer's dialog doesn't raise it; it sets how the driver
> handles the 600 dpi page we hand it.

Large sheets (D/E-size) are rendered in horizontal **bands** and joined
seamlessly, so full resolution is kept at any sheet size without ever building
one enormous bitmap. Because rendering at print resolution takes about a second a
page, printing now shows a **progress dialog with a Cancel button** instead of
appearing to freeze. **Print preview** deliberately renders at screen resolution
— it only ever shows a scaled-down page — so previewing a long set stays fast.

### Sharper zoom past 400% `1.2`

**What:** Zooming in past 400% stays **crisp** instead of turning into a blurry
upscale.

**How to use:** Just zoom in, up to 800%. Fine print and thin lines stay sharp.

**How it works:** The page used to stop re-rendering at 400% and stretch the last
image. It now re-rasterizes at the real zoom, bounded by a per-page memory budget
so a huge E-size sheet can't exhaust memory.

### Sheet-number split reads rotated & scanned drawings `1.2`

**What:** The **Split by sheet number** wizard reads the box you draw even on
**rotated** plots, and OCRs it on **scanned** sets automatically.

**How to use:** **PDF Tools ▸ Split by sheet number**, box the sheet number. The
preview now shows the number on rotated plots (where it used to say "nothing
found"); scanned sets are OCR'd when Tesseract is installed — no Settings switch
first.

**How it works:** AutoCAD plots are almost always saved rotated. The box is
converted into the page's own orientation before the text is read, and the preview
and the split now share one read — so what you see is what you get.

### Files that can't have a markup database now open anyway `1.2`

**What:** A PDF whose **filename is too long** or contains characters the system
won't accept used to fail to open. Now it opens for viewing.

**How to use:** Just open it. Markup and saving are grayed out (a popup explains
why), but you can still **view, search, print** and use the **PDF Tools**. Rename
the file shorter/simpler to turn markup back on.

## What hasn't changed

- **The original is sacrosanct** — it is never written to.
- **The sidecar is the source of truth** — marks, order, TODO state, tags and
  cached extractions all persist there and round-trip exactly.
- **Everything is a standard PDF annotation on export**, so colleagues can view
  (and comment on) your redlines in their own tools.
- **Everything is undoable** — create, move, copy/paste, reorder, restyle, rename,
  delete.

## Quality

The suite runs headless in CI and stands at **354 tests**. Each change went
through an independent adversarial review — which caught, among other things, a
coordinate mix-up in the sheet-number reader, a print dialog that could hang while
contacting a network printer, and a reference pane that held a full set of page
bitmaps while hidden. A user-runnable **`V1.2.0_TEST_PLAN.md`** walks through the
v1.2.0 features plus a regression pass.
