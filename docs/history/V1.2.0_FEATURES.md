# DSI Redline v1.2.0 — What's New & How It Works

This release is about **working faster with the marks you make** and **getting
the drawing out** — reusing and re-ordering marks, printing, and a workspace you
can arrange to suit your screen. Below is each new feature: **what it does**,
**how to use it**, and a short **how it works** for the technically curious.

Everything still rests on DSI Redline's hybrid storage — your **original PDF is
never modified**, marks are written into a `<name>.marked.pdf` copy as standard
PDF annotations, and app-only state lives in a `<name>.markup.db` SQLite
**sidecar**. Every edit is a command on the undo stack, so **everything is
undoable**.

---

## 1. Movable, floatable tabs

**What:** The five main panes — **Viewer, TODO, Wire Numbers, Component Labels,
PDF Tools** — are no longer fixed tabs. They behave like the Comments and
Navigation sidebars: you can pull a tab into its **own window** (put the TODO
list on a second monitor next to the drawing) or dock it to another edge.

**How to use:** **Drag a tab's title bar** out to float it, or onto another edge
to dock it; drop it back on the tab strip to re-tab. Closed a pane by accident?
Reopen it from **View ▸ Panes**. **View ▸ Reset panel layout** snaps everything
back to the default, and your arrangement is **remembered between sessions**.

**How it works:** Each pane is now a dockable widget instead of a page in a tab
strip. A thin compatibility layer keeps the rest of the app talking to them as
though they were still tabs, so nothing else changed. The saved layout is
version-stamped, so upgrading cleanly falls back to the tidy default the first
time. (Two floating windows won't merge into one — that specific operation is a
known toolkit hang, so it's deliberately disabled; every other arrangement
works.)

---

## 2. Copy & paste marks

**What:** Copy and paste text boxes, callouts, rectangles, arrows and clouds —
within a page or across pages.

**How to use:** Select one or more marks, **`Ctrl+C`** (or right-click ▸
**Copy**), then **`Ctrl+V`** (or right-click empty canvas ▸ **Paste … here**).
Multi-select copies them together; repeated pastes **cascade** so they don't
stack exactly on top of each other; the pasted marks land **selected**, and the
whole paste is a **single undo step**. (With no mark selected, `Ctrl+C` still
copies selected *text*, as before.)

**How it works:** Copying stores a snapshot of each mark. Pasting clones them
with fresh identities, offsets them so they're easy to grab, drops them on top of
the stack, and commits them as one undo action.

---

## 3. Format painter

**What:** Copy one mark's **look** onto another — colour, opacity, fill, border
width and font — without touching the target's text or position.

**How to use:** Right-click a mark you like ▸ **Copy formatting**, then right-click
another mark **of the same type** ▸ **Paste formatting**. (The Paste-formatting
entry stays greyed until you've copied a matching style.)

**How it works:** Only the styling fields are copied, never the geometry or the
words — the same idea as a word processor's format painter. It's restricted to
the same mark type so a rectangle's fill can't land on an arrow that has no fill.

---

## 4. Sticky styles

**What:** New marks **remember your last look**, so you don't re-pick colour,
font and fill for every single mark.

**How to use:** Set a colour / font / fill on a new text box or callout; the
**next** one starts with those same settings. The **text is never carried over**
— only the styling.

**How it works:** When you style a new mark, those choices feed back into the
tool's defaults, so the next mark inherits them until you change them again.

---

## 5. Stacking order

**What:** Control which overlapping mark sits **on top**.

**How to use:** Right-click a mark ▸ **Order ▸ Bring to Front / Bring Forward /
Send Backward / Send to Back**.

**How it works:** Every mark carries a stacking value. New and pasted marks land
on top; reordering is undoable, **persists** in the sidecar, and is **honoured in
the exported PDF**, so the layering you see is the layering colleagues see.

---

## 6. Smoother "Draw new"

**What:** Drawing a new mark on top of an existing one no longer interrupts you.

**How to use:** When you start a mark over an existing one, you're asked once —
**Edit this / Draw new / Cancel**. Choose **Draw new** and you can finish placing
the object with **no second pop-up** breaking your stroke.

**How it works:** The "draw new" choice is remembered for that single placement,
so the prompt asks once and then gets out of the way.

---

## 7. Rename a commenter

**What:** Change **who a mark is by** — handy for fixing an imported author name
(e.g. a batch of marks that came in as `AutoCAD`).

**How to use:** **Double-click a name** in the Comments **By** column, or the TODO
**Commenter** column. Confirm, type the new name — and if several marks share
that name, you can **rename them all at once**. It's undoable.

**How it works:** The rename is one undoable action (a single macro when you
rename a whole group), and the Comments sidebar and TODO list update together
because they react to the same change.

---

## 8. View-only mode for files that can't have a sidecar

**What:** A PDF whose **filename is too long** or contains characters the system
won't accept for its `<name>.markup.db` sidecar used to fail to open. Now it
**opens for viewing** instead.

**How to use:** Nothing extra — just open the file. It opens with **markup and
saving greyed out**, and a popup explains why. You can still **view, search,
navigate, print** and use the **PDF Tools**. To turn markup back on, **rename the
file** to something shorter / simpler and open it again.

**How it works:** The app can't create the markup database next to such a file,
so instead of aborting the open it falls back to a harmless "do-nothing"
sidecar — enough to view the drawing — and disables the tools that would need to
save, telling you exactly how to fix it.

---

## 9. Print — with preview and "Include markups"

**What:** Print the drawing, with or without your marks, straight to any
installed printer.

**How to use:** **File ▸ Print…** (**`Ctrl+P`**) opens the **standard system
print dialog** — pick the printer, copies, orientation and page range, then
print. **File ▸ Print preview…** shows the pages first and adds an **Include
markups** toggle (**on by default**) so you can print either the marked-up
drawing or a **clean** copy.

**How it works:** Each page is rasterised — with the marks baked in, or clean if
the toggle is off — fitted and centred on the sheet. The printer is set up
**without** the capability query that used to make the dialog hang while
"contacting" a network printer, so the print dialog comes up promptly.

---

## 10. Sheet-number split that reads rotated & scanned drawings

**What:** The **Split by sheet number** wizard (in PDF Tools) now reads the sheet
number from the box you draw even on **rotated** drawings — and OCRs the box on
**scanned** sets automatically.

**How to use:** **PDF Tools ▸ Split by sheet number**, drag a box around the
sheet number. The **preview now shows the number** on rotated plots (where it
used to show "nothing found"), and the split names each file by that number. On a
**scanned** set, the box is **OCR'd automatically** when Tesseract is installed —
no Settings switch to flip first.

**How it works:** AutoCAD plots are almost always saved with a page rotation. The
box you draw is turned into the page's own coordinate system before the text is
read, and the **preview and the actual split now use one shared read**, so what
you see is exactly what you get. Scanned pages fall back to OCR (then, if you've
enabled it, Claude) whenever the text layer is empty.

---

## 11. Sharper zoom past 400%

**What:** Zooming past 400% now stays **crisp** instead of turning into a blurry
upscale.

**How to use:** Just zoom in — up to 800%. Fine print and thin lines stay sharp.

**How it works:** The page used to stop re-rendering at 400% and simply stretch
the last image. It now re-rasterises at the actual zoom, **bounded by a per-page
memory budget** so a huge E-size sheet can't exhaust memory while normal letter /
ANSI-B sheets render crisp all the way in.

---

## Design principles carried throughout

- **The original is sacrosanct** — it is never written to.
- **The sidecar is the source of truth** — marks, order, TODO state, tags,
  geometry and cached extractions all persist there and round-trip exactly.
- **Everything is a standard PDF annotation on export**, so colleagues can view
  (and comment on) your redlines in their own tools.
- **Everything is undoable** — create, move, copy/paste, reorder, restyle,
  rename, delete.
- **The workspace is yours** — arrange the panes however suits your screen; the
  layout comes back the way you left it.

## Quality

Every feature ships with automated tests (the suite has **307** and runs headless
in CI), and each change went through an independent adversarial review pass —
which caught, among other things, a coordinate mix-up in the sheet-number reader
and an edge case where a closed floating pane could still be treated as active.
A user-runnable **`V1.2.0_TEST_PLAN.md`** in the repository walks through each new
feature plus a regression pass.
